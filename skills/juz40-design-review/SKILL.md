# Дизайн-ревью JUZ40

Скилл сравнивает живую страницу с макетом и собирает расхождения в Figma. Результат: страница в workspace пользователя, где у каждого расхождения есть два скрина, значения и ссылки.

## 1. Получи ссылки

Сначала получи ссылку на workspace. Без неё не начинай сверку: собирать результат будет некуда, и работа пропадёт на последнем шаге.

Если ссылок нет, отправь это сообщение и остановись. Если часть ссылок уже есть, спроси только недостающие.

```
Для ревью пришлите 3 ссылки:
1. Workspace в Figma: файл или проект, куда собрать скрины
2. Макет: фрейм или секция в Figma
3. Дев: адрес страницы на стенде
```

## 2. Проверь workspace

Определи тип ссылки:

| Ссылка | Что делать |
|---|---|
| `figma.com/design/:fileKey/...` | Собери доску на новой странице этого файла |
| `figma.com/design/:fileKey/branch/:branchKey/...` | Используй `branchKey` как `fileKey` |
| `figma.com/files/.../project/:projectId` | На шаге 7 создай файл в этом проекте |
| Ссылка на команду, организацию или «Недавние» | Попроси ссылку на файл или проект |
| `/board/`, `/slides/`, `/make/` | Попроси ссылку на файл Figma Design |

Для файла вызови `create_session`, затем `get_metadata` без `nodeId`. Для проекта вызови `whoami` и возьми `planKey`. Если планов несколько, спроси, какой использовать.

Если доступа нет или в `whoami` у пользователя место только для просмотра, попроси другую ссылку или доступ на редактирование. Сделай это сейчас, а не после сверки.

В workspace только добавляй новую страницу или файл. Существующие страницы не меняй: там чужая работа.

## 3. Подготовь снятие скринов

Скрипт `scripts/devshot.py` снимает дев через установленный Chrome. При первом запуске выполни:

```bash
python3 scripts/devshot.py setup
```

Если стенд требует вход, запусти команду ниже в фоне и попроси пользователя войти в открывшемся окне и закрыть его:

```bash
python3 scripts/devshot.py login "<адрес дева>"
```

Не спрашивай пароли и коды в чате. Пользователь вводит их только в этом окне.

Складывай файлы в `~/.juz40-design-review/runs/<фича>-<дата>/`.

## 4. Составь пары экранов

Для каждого экрана определи фрейм, адрес, ширину и состояние. Ширину бери из фрейма.

- Если ссылка ведёт на страницу или секцию, найди фреймы через `get_metadata`.
- Если фрейм нельзя сопоставить с адресом уверенно, покажи пары пользователю и спроси.
- Если на адаптив есть отдельные фреймы, проверь каждую ширину.
- Если состояние требует изменить данные (отправить форму, оплатить, удалить), спроси пользователя. Без согласия занеси его в «Не проверено».

## 5. Сними макет и дев

**Макет.** Загрузи инструкцию `figma-design-to-code` и вызови `get_design_context` и `get_variable_defs` для фрейма. Затем вызови `get_screenshot` с `maxDimension`, равным удвоенной длинной стороне фрейма, и скачай PNG по выданному адресу.

**Дев.** Сними страницу:

```bash
python3 scripts/devshot.py capture "<адрес>" --out <папка> --name <экран> --width 1440 --height 900
```

Скрипт сохранит `<экран>.png` и `<экран>.json` с размерами, цветами, шрифтами и отступами элементов.

Полезные параметры: `--click` и `--hover` открывают состояние, `--wait-for` ждёт элемент, `--mask` закрывает элемент на скрине. Если в ответе `needs_login: true`, вернись к `login`.

Скрины попадут в общий файл. Закрывай через `--mask` реальные персональные данные: ФИО, телефоны, ИИН, оценки учеников. Если закрыть нельзя, спроси пользователя перед загрузкой.

## 6. Сравни

Прочитай `references/compare.md` и следуй ему. Сравни значения и изображение: значения находят мелкие отличия, изображение находит пропавшие элементы и сломанную вёрстку.

```bash
python3 scripts/devshot.py pair <макет.png> <дев.png> --out <папка>/pairs
```

Команда нарежет экран на парные фрагменты. Посмотри каждый фрагмент.

Для каждого расхождения вырежи скрин макета и дева, координаты указывай в пикселях фрейма и страницы:

```bash
python3 scripts/devshot.py crop <исходный.png> <вырезка.png> --box X,Y,W,H
```

Сохрани JSON-ответ команды: `width`, `height` и `highlight` нужны для доски.

**Если расхождений нет**, ничего не создавай в Figma. Сообщи, какие экраны и ширины проверены, и что осталось непроверенным.

## 7. Собери доску

1. Загрузи инструкцию `figma-use` перед первым вызовом `use_figma`.
2. Если workspace это проект, создай файл `Дизайн-ревью · <фича>` через `create_new_file` и вызови `create_session`.
3. Возьми код из `assets/board_builder.js`, подставь данные в `DATA` и вызови `use_figma` с `mode: "init"`. Сохрани `pageId` и `rootId`.
4. Для каждого экрана вызови `use_figma` с `mode: "screen"`. Ответ вернёт `placeholders`: узлы для скринов.
5. Вызови `upload_assets` с `fileKey`, `count`, `currentPageId`, `nodeIds` из `placeholders` и `scaleMode: "FILL"`. Порядок адресов совпадает с порядком `nodeIds`.
6. Загрузи каждый скрин в свой адрес:

```bash
curl -sS -X POST -H "Content-Type: image/png" --data-binary @<вырезка.png> "<адрес загрузки>"
```

Если страницу создать нельзя (лимит страниц в тарифе или нет прав), сообщи причину и попроси другой workspace. Скрины сохранены, повторять сверку не нужно.

**Текст на доске.** Пиши коротко и на «вы». Заголовок называет отличие: «Кнопка меньше на 8 px», а не «Несоответствие размера кнопки». Не ставь длинное тире и точку в конце строки.

## 8. Проверь и отчитайся

Вызови `get_screenshot` для `rootId`. Проверь, что все скрины загрузились, рамки стоят на нужных элементах, а текст не обрезан. Исправь только сломанные узлы.

После проверки удали папку этого запуска: в ней остаются скрины дева.

В чате сообщи:

- ссылку на доску: `https://www.figma.com/design/<fileKey>?node-id=<rootId, где ":" заменено на "-">`;
- число расхождений: критичных, важных, мелких;
- критичные расхождения одной строкой на каждое;
- что не удалось проверить и почему.
