# Правила сравнения

## Порядок

1. Сопоставь элементы макета и дева по тексту, затем по роли и положению.
2. Проверь структуру: все ли элементы есть, нет ли лишних, совпадает ли порядок.
3. Сравни значения из таблицы допусков.
4. Посмотри парные фрагменты из `pair`. Ищи то, чего нет в значениях: обрезанный текст, наезды, сдвиг сетки, не те иконки и изображения.
5. Объедини расхождения с одной причиной.

## Допуски

Значения в пределах допуска не считай расхождением.

| Свойство | Допуск | Мелочь | Важно |
|---|---|---|---|
| Размер и положение | до 1 px | 2–3 px | от 4 px |
| Отступы и gap | до 1 px | 2–3 px | от 4 px |
| Радиус | до 1 px | 2–3 px | от 4 px |
| Размер шрифта | 0 | | любое отличие |
| Насыщенность шрифта | 0 | | любое отличие |
| Семейство шрифта | 0 | | любое отличие |
| Межстрочный интервал | до 1 px | 2–3 px | от 4 px |
| Межбуквенный интервал | до 0,1 px | больше 0,1 px | |
| Цвет | до 2 единиц в канале RGB | заметен только при сравнении значений | заметен на скрине или нарушает токен |
| Прозрачность | до 0,02 | до 0,1 | больше 0,1 |
| Тень | до 1 px | небольшое отличие | тени нет или она другая по типу |

## Критичность

**Критично.** Пользователь не может выполнить задачу или видит неверную информацию:

- нет элемента или действия;
- кнопка ведёт себя не так, как в макете;
- текст обрезан, элементы наезжают друг на друга;
- вёрстка ломается на ширине из макета;
- неверный смысл текста.

**Важно.** Пользователь видит отличие:

- другой компонент, вариант или иконка;
- другой шрифт, цвет или размер;
- отступ отличается от 4 px;
- другой порядок элементов;
- опечатка или другая формулировка.

**Мелочь.** Отличие видно только при точном сравнении.

## Что не считать расхождением

- Данные, которые меняются: имена, даты, суммы, число записей. Проверяй только формат и вёрстку.
- Различия сглаживания шрифта между Figma и браузером.
- Системные элементы браузера: полоса прокрутки, автозаполнение.
- Контент-заглушки макета, если реальный контент подходит под ту же вёрстку.

## Как объединять

Одна причина значит одна карточка. Если кнопка неверного цвета на пяти экранах, создай одну карточку на первом экране и перечисли остальные в `note`.

Расхождения одного элемента объединяй: размер, цвет и радиус кнопки попадают в одну карточку с тремя строками таблицы.

## Формат расхождения

| Поле | Пример |
|---|---|
| `id` | `D-01` |
| `severity` | `critical`, `major` или `minor` |
| `title` | `Кнопка меньше на 8 px` |
| `rows` | `{ "property": "Высота", "design": "48 px", "dev": "40 px" }` |
| `note` | `Также на экранах: Курсы, Профиль` |

Если у значения есть токен, укажи его рядом: `#1F6FEB (primary/500)`.

Если элемента нет на деве, задай `dev: null` и покажи скрин макета. Если лишний элемент есть только на деве, задай `design: null`.

## Что занести в «Не проверено»

- Экран без фрейма или без адреса.
- Состояние, которое нельзя открыть без изменения данных.
- Страницу, которая не открылась.
- Элементы, скрытые через `--mask`, если на них есть расхождения.
